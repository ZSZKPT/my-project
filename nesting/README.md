# 布序 · 数码印花裁片智能排料

可运行的本地网页版应用：导入所有 JPG 裁片文件，逐片确认尺寸和轮廓，在默认 **1580 mm** 门幅内排料。**每文件一片，不需要设置数量**，重复名称也独立保留。默认轮廓净间距 **3 mm，可调整**。方向只有 0° / 180°，旋转时印花与轮廓整体一致，无镜像。

## 启动

需要 Python 3.12+ 和现代 Chrome / Edge。首次安装需要联网下载 PyPI 依赖，运行与素材处理均在本机，无外部 CDN、账号或云端上传。

Windows：安装 Python（含 Python Launcher），解压后双击 `START-WINDOWS.cmd`（也可用 `start.cmd`）。macOS / Linux：在解压目录运行 `bash start.sh`。浏览器访问终端提示的本机地址，关闭终端会停止服务。Windows 启动脚本提供源码，当前验证平台为 Linux + Chromium；没有交付或验证 Windows EXE。

也可手动运行：

```sh
cd nesting
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python server.py --port 8765
```

Windows 手动命令将 `python3` 换成 `py -3`，后续解释器换成 `.venv\Scripts\python.exe`。端口占用可通过 `--port 8766` 调整。服务仅监听 `127.0.0.1`，不要通过代理暴露到公网。

## 实际使用

1. 点击“选择文件”，或将所有裁片 JPG 拖入左侧。PNG、SVG 也支持。应用按文件逐个导入，不合并相同款号、尺码和名称。
2. JPG 默认识别白色背景：背景色差阈值默认20，调大可排除更多接近背景色的像素；去噪面积默认0，不自动丢弃小区域。PNG 可选透明通道，阈值默认128；也可明确选矩形模式。
3. 如果所有图片具有同一实际 DPI，导入时填写“共同 DPI”。未填写时读取文件内 DPI；没有可信尺寸时，进入每片的核对窗口填写实际宽、高，单位mm。这里是**整张图片画布的尺寸**，含白边，轮廓按相同比例转换。不可把像素数当成毫米。若长宽改变比例，图像也会按输入尺寸拉伸，请核对实际尺寸。
4. 点击裁片卡片，核对绿色轮廓是否包含全部裁片、是否与印花一致；确认尺寸和方向，勾选确认。JPG 有白色图案、阴影、细线或复杂背景时，颜色识别可能不可靠，**必须人工核对**；可重新导入调整阈值，或使用配套SVG。没有自动理解缝份、裁切线和成品线。
5. JPG“使用配套 SVG 切割轮廓”：SVG 必须与 JPG 共用完整画布坐标，轮廓投影到相同实际宽高；选择指定切割元素ID后预览叠加。导入SVG若有多个图形，也会要求填写唯一切割元素ID。
6. 门幅默认1580，左右预留各10（可设0），有效宽1560。净间距默认3，可设0至100。出血扩张默认0；若设置，按“轮廓 + 出血 + 曲线保守余量”作为占用，**两个占用外轮廓之间**再保持所设净间距，不是两片各留3。
7. 所有裁片核对完成后，点击“开始智能排料”。可停止并保留当前最佳可行方案。点击“载入演示”可体验已知尺寸的虚构三角样本。
8. 点击画布裁片，可拖动或输入毫米坐标、旋转180°、锁定/解锁。拖动期间约每140毫秒请求一次复核并标红冲突，拖动结束后再进行完整复核；锁定片不会被后续优化移动。Alt+拖动平移、工具栏缩放、滚动查看长布。禁止旋转的裁片没有180°入口。
9. 手动修改可撤销/重做。修改来源、尺寸或轮廓会清空已有排料，以免沿用失效位置。修改门幅、间距后重新复核，或重新排料。发生冲突、缺片、超宽时，生产导出被阻止。
10. “保存项目”下载含原始素材、设置、轮廓和坐标的JSON。空排料/尚未确认的项目也可保存并重新打开。不会自动保存到浏览器，退出前请下载项目文件。

## 生产文件

- **生产SVG**：`width`、`height`为毫米，`viewBox`使用同一毫米坐标；图像位置与轮廓使用同一变换。嵌入原始JPG/PNG/SVG数据字节，不在排料时重采样。按占用轮廓裁剪图像，防止JPG白底覆盖相邻裁片。标签不进入生产输出。
- **分段ZIP**：默认每2000 mm分一段，分段长度可调。包含连续坐标SVG、`manifest.json`、裁片坐标CSV、完整项目及生产说明。每段无重叠，各段起止坐标精确接续；跨段裁片在两段中按各自视窗裁剪。打印软件不要另加重叠，不要重复输出段间部分。
- **预览PNG**：宽最多1600像素、高最多8000像素，带“非生产比例”字样，仅用于检查，不作为生产栅格图，不宣称生产DPI。
- **坐标CSV**：毫米位置、角度、文件、款号和尺码，已处理公式注入。
- 不处理ICC转换，不生成缺失出血图像。源图ICC字节保留在嵌入图片内，SVG/RIP的解释取决于实际打印软件。**使用100 mm校准方块验证设备尺寸、方向、分段衔接及色彩后再生产。** 当前未连接打印机、未验证RIP兼容性。

DXF、PDF、TIFF、生产级大幅面栅格流式输出尚未实现。当前生产路径是毫米SVG及分段SVG。图片默认按确认后的外轮廓打印，不自动区分衣片的成品线、裁切线、缝份。

## 算法与精度

后台采用 Shapely / GEOS，网页使用原生JavaScript与SVG。Python本地服务用于可靠多边形运算、SVG单位解析与打包；不需要Node.js来运行应用。优化在后台线程执行，网页轮询当前最佳方案，不阻塞拖动之外的页面响应。

先构造外接矩形行排可行基线，再根据面积/高度/宽度排序，搜索轮廓顶点接触和水平采样位置，比较0°/180°，多起点交换/随机重排。缓存各片两个方向的几何和候选顶点，使用STRtree空间索引筛选碰撞对象。候选位置是有限采样，**未实现全NFP、全局最优证明或专用空隙碎片度目标**；不承诺绝对最省料。细长空隙可能未被候选点覆盖。搜索停止/超时会保留已独立复核的最佳完整方案。

固定种子、相同输入、相同搜索轮数、同版本，在完成全部轮数且不触及时间上限时可复现。时限中断点受机器速度影响。比较表未产生“真实轮廓初始方案”时表示该轮没有在预算内完成，并非零耗时通过。

- PNG/JPG：以选中像素的整个像素单元合并成外轮廓，不对最终轮廓简化；填平内部孔洞，避免把内部透明图案当成可套排区域。背景识别的准确性取决于原图和用户确认。
- SVG：支持闭合path、基本Shape、单位及组变换，要求指定唯一切割元素。曲线按毫米弧长采样，并为曲线轮廓增加0.1 mm保守余量；最终碰撞复核使用同一高精度离散轮廓，不宣称原生曲线解析精确碰撞。直线轮廓同样预留0.1 mm，以统一安全边界。
- 距离比较容差为0.000001 mm，交叠面积容差为0.000001 mm²。不自动修复自相交轮廓。
- SVG首版拒绝脚本、外部资源、use、CSS样式、mask、clipPath、filter及动态元素。请在矢量软件中展开样式/实例，再导入。制作切割线时给闭合图形设置唯一ID。
- JPG含EXIF旋转会要求先将方向真正应用后另存，避免不同软件对方向解释不一致。
- 首版上限500片/任务，20百万像素/图、24MB原始素材/图、100MB请求/项目、最多100个独立外轮廓/文件、50000点/轮廓。分段最多500段，预计内容超过256MB会阻止导出。超限时请分批，不会静默降分辨率。
- 时间上限控制启发式候选搜索；初始可行基线、独立复核与文件处理在预算之外，不能保证整个HTTP请求严格按秒结束。

## 测试

```sh
.venv/bin/python -m unittest discover -s tests -v
```

浏览器验证为可选开发依赖，正常运行不需要安装：

```sh
npm ci
npx playwright install chromium
# 先在另一个终端启动 server.py
npm run test:browser
```

已安装Chromium时可设置 `CHROMIUM_PATH` 指向可执行文件；`NESTING_URL`可调整测试服务地址。端到端测试会下载文件至临时目录，不操作真实生产素材。测试结果及实测对比见 `VALIDATION.md`。

## 文件结构

`web/` 中文界面；`geometry.py` 几何及独立复核；`engine.py` 排料；`assets.py` 素材和轮廓；`exporting.py` 生产输出；`server.py` 本地HTTP服务；`examples/` 虚构样本；`tests/` 自动化测试；`requirements.lock` 完整Python依赖版本；`package-lock.json` 可选浏览器测试依赖锁。


## Windows 双击无反应

下载更新包后解压到一个新文件夹，双击 `START-WINDOWS.cmd`。该入口使用保留窗口模式，启动器会显示Python版本、依赖安装进度，并在服务健康检查通过后打开浏览器。首次安装可能需要数分钟，请保留窗口。失败时查看同目录 `startup.log`，不要反复双击启动。若未找到Python，窗口会提供官方下载地址；安装时勾选 Add python.exe to PATH。旧目录中的 `.venv` 不需要复制到新目录。

Windows启动修复在Linux上完成Python语法检查和模拟进程测试；没有实际Windows机器，不能据此宣称Windows端已实测成功。
